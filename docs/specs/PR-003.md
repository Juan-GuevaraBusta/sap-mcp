# PR-003 · Modelo de conocimiento v0 y Knowledge Store

## Objetivo

Se pueden guardar y recuperar pantallas, elementos, aristas de navegación, evidencia e hipótesis, versionados y aislados por instalación. Una hipótesis o un elemento no llega a `validated` sin evidencia.

- `product_context.md` §8.1, §8.2 y §8.3.
- Subconjunto del MVP que nombra el roadmap: `Screen`, `UIElement`, `NavigationEdge`, `Evidence`, `Hypothesis`, más `Installation` y `KnowledgeRevision`.

Este PR asume que PR-001a ya está en `main`.

## Decisión abierta 2

`docs/decisions.md` decisión #2 (SQLite vs Postgres) bloquea este PR. Propuesta para cerrarla al aprobar la spec:

- **Decisión:** SQLite detrás de un `Protocol` `KnowledgeRepository`. La base puede ser un archivo o `:memory:`.
- **Descartado:** Postgres en el MVP. Hay un solo proceso y no hay escritores concurrentes. El skill `migration` cubre un cambio de motor si el volumen lo pide.
- **Consecuencia:** el store arranca sin servicio externo. Cambiar de motor más adelante exige una migración con ADR.

Aprobar esta spec incluye aprobar ese texto. La ADR la escribe el Orquestador en `docs/decisions.md`, porque ese archivo está fuera de `write_paths`. Hasta que la ADR esté registrada, el Implementer no empieza.

## Contrato

Models en `src/sap_mcp/knowledge/models.py`. Store en `src/sap_mcp/knowledge/store.py`. Pydantic v2 con `extra="forbid"`.

```python
class KnowledgeState(StrEnum):
    discovered = "discovered"
    documented = "documented"
    experimentally_observed = "experimentally_observed"
    validated = "validated"
    conflicted = "conflicted"
    stale = "stale"
    deprecated = "deprecated"

class Installation(BaseModel):
    installation_id: str
    name: str

class Evidence(BaseModel):
    evidence_id: str
    installation_id: str
    kind: Literal["observation", "document"]
    observation_id: str | None = None   # str opaco; no importa Observation
    source: str                         # método de detección o cita documental
    recorded_at: datetime

class UIElement(BaseModel):
    element_id: str
    installation_id: str
    screen_id: str
    stable_key: str                     # el stable_id del acuerdo con PR-002
    name: str
    kind: str
    state: KnowledgeState = KnowledgeState.discovered
    evidence_ids: tuple[str, ...] = ()

class Screen(BaseModel):
    screen_id: str
    installation_id: str
    name: str
    state: KnowledgeState = KnowledgeState.discovered

class NavigationEdge(BaseModel):
    edge_id: str
    installation_id: str
    from_screen_id: str
    to_screen_id: str

class Hypothesis(BaseModel):
    hypothesis_id: str
    installation_id: str
    element_id: str
    statement: str
    state: KnowledgeState = KnowledgeState.discovered
    evidence_ids: tuple[str, ...] = ()

class KnowledgeRevision(BaseModel):
    revision_id: str
    entity_type: Literal["screen", "element", "edge", "evidence", "hypothesis"]
    entity_id: str
    installation_id: str
    revision: int          # empieza en 1
    payload: dict
    created_at: datetime

class KnowledgeRepository(Protocol):
    def save_installation(self, item: Installation) -> None: ...
    def save_screen(self, item: Screen) -> KnowledgeRevision: ...
    def save_element(self, item: UIElement) -> KnowledgeRevision: ...
    def save_edge(self, item: NavigationEdge) -> KnowledgeRevision: ...
    def save_evidence(self, item: Evidence) -> KnowledgeRevision: ...
    def save_hypothesis(self, item: Hypothesis) -> KnowledgeRevision: ...
    def get_element(self, installation_id: str, element_id: str) -> UIElement: ...
    def revisions_for(self, installation_id: str, entity_id: str) -> tuple[KnowledgeRevision, ...]: ...


def ensure_can_validate(evidence_ids: tuple[str, ...]) -> None:
    """Lanza ValueError si evidence_ids está vacío.

    save_element y save_hypothesis la llaman cuando state es validated.
    """
```

SQLite guarda el payload JSON de cada revisión. Un segundo `save_*` de una entidad que ya existe inserta otra fila con `revision + 1` y no actualiza la fila anterior.

## Invariantes

- Toda lectura y escritura lleva `installation_id`. `get_element` pedido con la instalación equivocada lanza `KeyError`.
- La revisión anterior se puede leer después de un segundo `save_*`, con el mismo contenido.
- `validated` con `evidence_ids` vacío no se persiste.
- Cerrar el store y volver a abrir el mismo archivo devuelve el mismo elemento y las mismas revisiones.

## Errores

- Entidad ausente, o entidad de otra instalación: `KeyError`.
- `save_element` o `save_hypothesis` con `state=validated` y `evidence_ids` vacío: `ValueError`. La base queda como estaba.
- Payload JSON ilegible al leer: la excepción sube. No se traga ni se sustituye por un valor por defecto.

## Acuerdos con PR paralelos

Acuerdo con PR-002, fijado antes de despachar. Ninguno de los dos importa el código del otro.

- `ElementRef` es el elemento observado en vivo. `UIElement` es el elemento persistido.
- La identidad estable es un `str` opaco. En PR-002 se llama `stable_id`. Aquí, `UIElement.stable_key` guarda ese mismo string.
- Las coordenadas no forman parte de este modelo. Viven como evidencia de una observación en PR-002.
- `Evidence.observation_id` es un `str` opaco. Este PR no importa el tipo `Observation`.
- El PR que une ambos modelos es PR-007.
