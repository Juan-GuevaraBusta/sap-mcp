# PR-002 · Contrato de la capa de interacción

## Objetivo

Existe un contrato tipado que cualquier adaptador futuro (RFB, Playwright, UI Automation, API SAP) puede implementar, y el núcleo puede programar contra él sin conocer el protocolo.

## Contexto

- `docs/roadmap.md`, PR-002.
- `product_context.md` §5.5 (capacidades comunes del adaptador) y §8.2 (las coordenadas son evidencia de una observación, no la identidad permanente de un control).
- PR-004 será el primer adaptador real. Esta spec no lo anticipa.

Este PR asume que PR-001a ya está en `main`.

## Fuera de alcance

- Ningún adaptador real. Nada de framebuffer, clics ni websockets. El adaptador RFB es PR-004.
- Descubrir elementos a partir de píxeles. Lo hace PR-007.
- Modificar `pyproject.toml` ni `src/sap_mcp/__init__.py`.

## Contrato

Todo vive en `src/sap_mcp/interaction/contracts.py`. Models de Pydantic v2 con `extra="forbid"` y `frozen=True`.

```python
class BBox(BaseModel):
    x: int
    y: int
    width: int    # > 0
    height: int   # > 0

class ElementRef(BaseModel):
    stable_id: str          # min_length=1; identidad del control
    kind: Literal["button", "field", "menu", "table", "dialog", "message", "unknown"]
    label: str | None = None
    semantic: bool = False  # True solo si el adaptador declaró semántica
    bbox: BBox | None = None

class Observation(BaseModel):
    observation_id: str     # min_length=1
    captured_at: datetime
    width: int              # > 0
    height: int             # > 0
    elements: tuple[ElementRef, ...] = ()

class ElementList(BaseModel):
    elements: tuple[ElementRef, ...]

class Interaction(BaseModel):
    target_id: str          # un ElementRef.stable_id
    action: Literal["click", "type", "scroll", "key"]
    text: str | None = None

class Effect(BaseModel):
    before_id: str
    after_id: str
    changed: bool

class AdapterCapabilities(BaseModel):
    semantic: bool          # False cuando el adaptador solo tiene píxeles
    can_discover: bool
    can_interact: bool
    can_observe_effect: bool

class SessionContext(BaseModel):
    installation_id: str
    application: str | None = None
    session_id: str

@runtime_checkable
class InteractionAdapter(Protocol):
    def get_capabilities(self) -> AdapterCapabilities: ...
    def get_context(self) -> SessionContext: ...
    def observe(self) -> Observation: ...
    def discover_elements(self) -> ElementList: ...
    def interact(self, interaction: Interaction) -> None: ...
    def observe_effect(self, before: Observation) -> Effect: ...


def require_consistent(observation: Observation, capabilities: AdapterCapabilities) -> None:
    """Si capabilities.semantic es False y algún elemento tiene semantic=True, lanza ValueError."""
```

`require_consistent` es una función pura del mismo módulo. No vive dentro del validador de `Observation`, porque `Observation` no conoce al adaptador. El adaptador la llama antes de devolver la observación.

## Invariantes

- La identidad es `stable_id`. Dos `ElementRef` con el mismo `stable_id` y distinto `bbox` siguen siendo el mismo control. El test compara `stable_id`, no el modelo entero.
- Un adaptador con `semantic=False` no puede emitir un elemento con `semantic=True`. Lo garantiza `require_consistent`.
- El módulo no importa `vnc`, `playwright`, `websockets` ni `pillow`.
- `width` y `height` de `Observation` salen de la captura. No existe una constante 1280×800 en este módulo.

## Errores

- Campo desconocido en cualquiera de los models: `ValidationError`.
- `stable_id` vacío, o `width` / `height` no positivos: `ValidationError`.
- `require_consistent` incumplido: `ValueError`.

## Acuerdos con PR paralelos

Acuerdo con PR-003, fijado antes de despachar. Ninguno de los dos importa el código del otro.

- `ElementRef` es el elemento observado en vivo. `UIElement` es el elemento persistido.
- La identidad estable es un `str` opaco. En este PR se llama `stable_id`. En PR-003, `UIElement.stable_key` guarda ese mismo string.
- Las coordenadas viven solo en `bbox`, como evidencia de una observación.
- PR-003 referencia una observación con `Evidence.observation_id: str`, sin importar el tipo `Observation`.
- El PR que une ambos modelos es PR-007.
